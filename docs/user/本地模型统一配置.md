# 本地模型统一配置

本页是操作说明。模型事实来自 `data/providers`，启用集合与客户端 ID 映射来自
`data/local-model-set.json`。一条命令同步 AICLI 安装、Codex Desktop、OpenCode、
Toolkit 注册表及其本机镜像，并读回 Ollama 实际模型标识与清单哈希。

```powershell
# 在 AICLI 项目根目录预览
pwsh -NoProfile -File scripts/Sync-LocalModelConfiguration.ps1 -Json
# 应用
pwsh -NoProfile -File scripts/Sync-LocalModelConfiguration.ps1 -Apply -Json
```

当前集合为 Qwen3.8 27B、Qwen3.6 35B，以及各自的去限制版本，均为 262144 上下文。
35B 去限制版权重为文本模型；其他三个声明图像输入。各型号保留适合自己的参数，
不要求不同架构使用相同采样或吞吐指标。

## 调整本地推理批处理大小

批处理大小属于 Ollama 运行标签。统一入口可预览、应用并同步其参数层与 Provider
声明，消费者无需分别增加请求参数。下面只调整已验证需要缓解的普通 35B；已经为
128 的模型不会重新创建。省略 `-OllamaProfileId` 时才显式作用于整个集合：

```powershell
& .\scripts\Sync-LocalModelConfiguration.ps1 -OllamaNumBatch 128 -OllamaProfileId codex-ollama-review -Json
& .\scripts\Sync-LocalModelConfiguration.ps1 -OllamaNumBatch 128 -OllamaProfileId codex-ollama-review -Apply -Json
```

应用前核对原标签哈希；应用后直接读取 Ollama 清单与参数层，验证权重、配置、模板和
其他采样参数保持。参数步骤失败时用短期原生副本恢复并核对原哈希；只有恢复成功才
清理副本。如果回滚读回失败，错误会给出保留的恢复标签。多模型逐个处理，后一个失败
不代表前面已完成的更新被撤销；修复阻塞后重跑同一入口即可继续同步。

本机参数层读取使用消费者配置的可选 `ollamaModelsPath`，未指定时使用用户环境变量
`OLLAMA_MODELS`，再使用 Ollama 默认模型目录。实际清单哈希必须与 API 返回值相同。
模型路径仍由机器配置维护，本命令不迁移权重。

2026-09-16 对同一真实会话渲染文本进行交错冷加载验证：Qwen3.6 35B 使用 512 时
输出约 62–69 tokens/s，使用 128 时约 170–171 tokens/s，输入处理也改善。两种 API
共享该现象，不能仅因 `/v1/responses` 日志出现检查点就归因于 Responses 或缓存恢复。
普通 35B 因此采用 128；原本已为 128 的两款 27B 保持原参数与清单。
35B 去限制版在 128 下输出基本持平，但输入处理由约 4546 降至 2100 tokens/s；该模型
没有本次普通版的慢态证据，因此保留原先有效的 512，并将其显式写入声明。
统一维护不等于强制不同模型采用同一批处理大小。
权重、量化、采样、思考设置与 262144 上下文保持；这是一项已实测的运行配置缓解，
不保证任意显卡驱动或外部 GPU 负载下的吞吐。

恢复普通 35B 修改前的有效批处理大小（512），同样走唯一入口：

```powershell
& .\scripts\Sync-LocalModelConfiguration.ps1 -OllamaNumBatch 512 `
  -OllamaProfileId codex-ollama-review -Json
# 确认预览仅包含以上一项后，追加 -Apply 执行。
```

回滚会显式记录 512 并生成对应清单，不会伪称恢复了原先未声明 `num_batch` 的旧哈希。
启用的 Desktop 桥若缺少可重建构建产物，统一同步入口会先构建再安装；不会关闭正在
运行的桌面任务。只调整 Ollama 参数时，原模型 ID 与 HTTP 端点保持，下次请求即采用
运行标签的参数；目录快照的刷新仍遵循正常桌面重开边界。

运行标签采用 `型号-参数量[-变体]:上下文`，不含客户端品牌、用途别名或构建日期。
当前为 `qwen3.8-27b:256k`、`qwen3.6-35b:256k`、
`qwen3.8-27b-abliterated:256k`、`qwen3.6-35b-abliterated:256k`。
权重来源、版本和哈希仍保留在 Provider 声明中，不靠冗长菜单名称追踪。

## 快速增加、删除和换型

1. **增加或换型**：先在 Ollama 准备实际权重和正式运行标签，更新对应 Provider
   Manifest（配置声明）与 Codex catalog（模型目录）；确保 `ollamaArtifact` 的哈希、
   参数和能力与运行标签一致。新增 Profile 同时在集合 `clients` 中登记 OpenCode key
   和 Toolkit backend ID，再加入 `profiles`。同一模型只留一个启用配置。
2. **删除**：从集合的 `profiles` 移除该 Profile，暂时保留 `clients` 映射及 Provider
   声明供同步器定位旧客户端入口。该 Ollama 实例专供统一集合使用；应用同步前先核对
   所有保留标签及哈希，随后删除集合外的全部标签，包括手工添加的重复或临时标签。
   Ollama 清单数量与启用的本地模型数量一致，备份按 PCConfig 的源跟随规则传播删除。
3. 运行上面的统一命令。保留仍有效的用户默认项；默认项指向已移除的本地模型时，
   改到剩余集合首项。其他云模型、登录和 Provider 保持各自配置。

Codex Desktop 在引擎启动时读取模型目录。新增或删除后，在下一次正常退出、打开
桌面版时刷新；同步器不会中断正在运行的任务。首次启用桌面接入仍按
[桌面接入说明](Codex%20桌面本地模型.md) 构建并 Enable。

这个集合只管理本地模型。Codex Desktop 每次引擎启动时重新获取上游官方完整目录，
再合并本地条目；官方模型不采用固定允许列表，不因加入本地模型阻止 OpenAI 推送
新模型。启动快照随下一次启动刷新，官方发现失败时才使用当前引擎自带目录。

## 本机消费者路径

`%LOCALAPPDATA%\AiCliProfileManager\local-model-consumers.json` 记录本机路径；
它不进入公开源码。可用 `-ConsumerConfigPath` 指定其他机器的配置：

```json
{
  "openCodeConfig": "<OpenCode config path>",
  "openCodeProvider": "<existing local provider ID>",
  "toolkitRegistry": "<Toolkit default_backends.json path>",
  "registryMirror": "<local registry mirror path>",
  "ollamaOrigin": "http://127.0.0.1:11434"
}
```

模型存放、端口、登录启动和 E→G→H 备份归 PCConfig。权重不放材料库或 Git；
Git 维护配置和恢复方法。无需独立再建模型管理项目或常驻同步服务。

## 检查范围

普通增减以配置同步、哈希和读回为准，不要求每次运行全客户端 E2E（端到端验收）。
配置已同步与实跑已验证分别记录；未跑验收保留 `live_verified=false`，普通本地
工具路由可使用，不虚报通过。出现实际问题时再验证和修复受影响路径。

2026-09-15 的本机 256K 实测中，两款 27B 各三轮连续生成 512 token：官方版约
51.8 tokens/s，去限制版约 49.6–50.2 tokens/s。冷加载和首字等待另计。
Wallpaper Engine 使用原生应用规则在 `llama-server.exe` 运行时停止壁纸并释放内存，
退出后恢复。这里只针对加载本地 LLM 的进程，不针对 Ollama 桌面或后台服务本身，
也不对 OCR、ASR 的 Python 小模型进程设置停止规则。本机由 PCConfig 配置
`OLLAMA_KEEP_ALIVE=3m`，最后一个请求结束后空闲 3 分钟自动卸载，壁纸随之恢复；
客户端不设置永久保留模型的 `keep_alive=-1`。这会让下一次间隔较久的请求重新加载，
连续工具调用在短空闲窗口内仍可复用已加载模型。OCR、ASR 若通过 GPU 调度释放了已有 LLM，
壁纸也随 LLM 退出恢复。此结果是当时环境的实测，不保证任意后台负载下的速度。

并发沿用 `OLLAMA_NUM_PARALLEL=1` 和 `OLLAMA_MAX_LOADED_MODELS=1`：同一时间只生成
一个请求，多请求使用 Ollama 原生排队。它不长期锁住整个对话；多个客户端仍可能
轮流占用服务，做速度验收时只运行一个调用方。

同日后续验收：Ollama 桌面在重启时自动更新到 0.34.0。最终完全卸载后重载、各生成
512 token，官方 27B 为 58.246 tokens/s，去限制版为 47.073 tokens/s；空闲约 30.2 秒
自动卸载。更新后官方第一次样本曾为 24.548 tokens/s，随后热机约 61、重新冷加载约
58；根因未独立证明，因此保留异常，不承诺新版本或任意后台负载下都不波动。
上下文与量化未降低，未以预热替代冷加载验收。

2026-09-16 用户将空闲保留时间从 30 秒调整为 3 分钟，减少正常思考、工具调用和切换
窗口时反复加载。统一入口提供 `-OllamaKeepAlive 3m`，默认预览，追加 `-Apply` 写入
本机 Ollama 用户环境变量并读回。PCConfig 启动检查同步维护该机器值；已运行的 Ollama
需在没有活动请求时重新启动才采用新值，不重启 Codex/OpenCode，不增加预热服务。
该项只减少冷启动次数，不改变一次真正冷启动的耗时或模型输出速度。
