# 本地模型统一配置

本页是操作说明。模型事实来自 `data/providers`，启用集合与客户端 ID 映射来自
`data/local-model-set.json`。一条命令同步 AICLI 安装、Codex Desktop、OpenCode、
Toolkit 注册表及其本机镜像，并读回 Ollama 实际模型标识与清单哈希。

```powershell
# 在 AICLI 项目根目录预览
pwsh -NoProfile -File scripts/Sync-LocalModelConfiguration.ps1 -Json
# 应用
pwsh -NoProfile -File scripts/Sync-LocalModelConfiguration.ps1 -Apply -Json
```

当前集合为 Qwen3.8 27B、Qwen3.6 35B，以及各自的去限制版本，均为 262144 上下文。
35B 去限制版权重为文本模型；其他三个声明图像输入。各型号保留适合自己的参数，
不要求不同架构使用相同采样或吞吐指标。

## 快速增加、删除和换型

1. **增加或换型**：先在 Ollama 准备实际权重和正式运行标签，更新对应 Provider
   Manifest（配置声明）与 Codex catalog（模型目录）；确保 `ollamaArtifact` 的哈希、
   参数和能力与运行标签一致。新增 Profile 同时在集合 `clients` 中登记 OpenCode key
   和 Toolkit backend ID，再加入 `profiles`。同一模型只留一个启用配置。
2. **删除**：从集合的 `profiles` 移除该 Profile，暂时保留 `clients` 映射及 Provider
   声明供同步器定位旧模型。应用同步后，它从客户端选择集合退出，Ollama 对应已登记
   标签也被删除；备份按 PCConfig 的源跟随规则传播删除。
3. 运行上面的统一命令。保留仍有效的用户默认项；默认项指向已移除的本地模型时，
   改到剩余集合首项。其他云模型、登录和 Provider 保持各自配置。

Codex Desktop 在引擎启动时读取模型目录。新增或删除后，在下一次正常退出、打开
桌面版时刷新；同步器不会中断正在运行的任务。首次启用桌面接入仍按
[桌面接入说明](Codex%20桌面本地模型.md) 构建并 Enable。

## 本机消费者路径

`%LOCALAPPDATA%\AiCliProfileManager\local-model-consumers.json` 记录本机路径；
它不进入公开源码。可用 `-ConsumerConfigPath` 指定其他机器的配置：

```json
{
  "openCodeConfig": "<OpenCode config path>",
  "openCodeProvider": "<existing local provider ID>",
  "toolkitRegistry": "<Toolkit default_backends.json path>",
  "registryMirror": "<local registry mirror path>",
  "ollamaOrigin": "http://127.0.0.1:11434"
}
```

模型存放、端口、登录启动和 E→G→H 备份归 PCConfig。权重不放材料库或 Git；
Git 维护配置和恢复方法。无需独立再建模型管理项目或常驻同步服务。

## 检查范围

普通增减以配置同步、哈希和读回为准，不要求每次运行全客户端 E2E（端到端验收）。
配置已同步与实跑已验证分别记录；未跑验收保留 `live_verified=false`，普通本地
工具路由可使用，不虚报通过。出现实际问题时再验证和修复受影响路径。

2026-09-15 的本机 256K 实测中，两款 27B 各三轮连续生成 512 token：官方版约
51.8 tokens/s，去限制版约 49.6–50.2 tokens/s。冷加载和首字等待另计。
Wallpaper Engine 使用原生应用规则在 `llama-server.exe` 运行时停止壁纸并释放内存，
退出后恢复。此结果是当时环境的实测，不保证任意后台负载下的速度。
