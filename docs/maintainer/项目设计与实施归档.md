# AI CLI Profile Manager 当前维护契约

本文保留项目独有的产品取舍、跨仓库接口和恢复所需条件。命令用法以用户手册和实际帮助为准；已完成的施工、测试数字、安装版本和当时的运行状态以 Git 与对应发布回执为准。机器路径及安装事实由 PCConfig 管，仓库身份与同步由 GitHub 总索引管。本文不把历史一次性验收写成未来版本的通过证明。

## 产品与本人已定取舍

- 本产品让 Windows 11、PowerShell 7 用户用中文入口管理 Profile、启动原生 Codex CLI、Claude Code、当前官方 Rust Open Interpreter，并完成代理运维、诊断、自检、更新指引和退出。它是启动与运维层；终端交互、上下文、工具、权限及聊天历史仍属上游引擎。保留独立品牌 AI CLI Profile Manager、命令 aicli、MIT 项目许可与第三方许可证分离。不做 GUI、全屏 TUI、PTY 外壳、自研 Agent 或通用聊天库，不修改上游 CLI。
- 用户选定引擎、Provider、模型、地域、套餐与凭据来源，启动计划只影响目标子进程；不永久改全局 Provider 环境或覆盖上游基础配置、登录。不自动跨 Provider 故障转移或静默升级。native 展示脱敏的实际启动计划，eject 导出无秘密配方，保留脱离本工具的路径。
- 交互式 aicli start 保持上游权限语义。独立的 Codex machine harness 对当前及未来模型统一要求原生 danger-full-access 与 approvalPolicy=never，并回读真实权限身份；模型、Provider、线程和权限漂移均失败关闭。这个决定不把交互式 start 降权或升权。
- 公开第三方 Codex 路线须有真实 Responses 语义，不把 Chat Completions 冒充 Responses。受管 loopback 适配器只有经明确登记、真实验收才是窄例外。官方 Codex、Claude 和本地模型的能力不能凭第三方 Profile 名称推断。未通过当期 Windows 真实验证的 Provider 不标“可用”。

## Profile 身份与模型边界

- Provider Manifest 是无执行能力的数据，声明引擎、Provider、端点、transport、模型、认证、能力和兼容性；用户 Profile 只保存选择及秘密引用；启动计划在每次运行时生成。稳定 Profile ID 不因模型别名、用户可见名称或退役迁移而暗改绑定。退役 codex-deepseek、claude-deepseek、oi-deepseek 的 ID/templateId 要精确识别并拒绝，用户原文件和 SecretRef 保留。
- Qwen 云端 Codex 只开放两个隔离 exact Workspace paygo Responses 入口：codex-qwen3-7-max-paygo → qwen3.7-max-2026-06-08，codex-qwen3-8-max-paygo → qwen3.8-max-0902。前者是本人后续明确决定，对先前“Qwen3.7 全家族退役”作窄范围修正；通用 alias、旧 Profile、Plus、preview、其他日期及 native model/fallback 绕过继续退役。两入口均单候选、无 fallback，用户 max 映射原生 xhigh；同一 Workspace 凭据域才可显式复用 SecretRef。
- GLM 中国区 Codex exact 入口是 codex-glm-5-3 → glm-5.3 与 codex-glm-5-3-flash → glm-5.3-flash，分别使用独立 Responses 模型目录和显式能力声明。DeepSeek 主入口为 codex-deepseek-flash → deepseek-flash；deepseek-v4-pro 只保留独立 CLI Profile，不进入桌面菜单。旧 DeepSeek 模板及旧验收不得复活为 Claude Code 或 Open Interpreter 的公开入口。
- 本地模型的 Provider 事实仍在既有 Manifest；data/local-model-set.json 只选启用集合和稳定客户端 ID。scripts/Sync-LocalModelConfiguration.ps1 负责同步 AICLI、Desktop、OpenCode、Toolkit 与本机镜像，机器路径及运行/备份归 PCConfig。日常增减做必要配置检查和读回；实际故障再定向验证，不机械要求每次全客户端 E2E。固定型号兼容入口与主用/复核入口分开，菜单显示真实型号而不泄露内部 main/review 标签。
- 原生 OpenAI 模型目录从当前官方引擎动态发现，再合并 AICLI 已配置的 exact 云端及本地模型；不得用固定版本路径或旧缓存替代当前官方目录。本地 Qwen 受管目录保持 262144 上下文、在 235929（90%）自动压缩；AICLI 自接入的非 OpenAI Codex 模型按各自最大上下文的 90% 设置阈值。各模型窗口、压缩和能力由其 Manifest/catalog 明确声明，不能从另一 Provider 继承；未知第三方 Claude 模型不猜窗口，也不关闭上游溢出保护。

## 原生连续性与后台协作

- 原生 ChatGPT + Codex 是第三方连续性的基准。官方 Profile 不附加第三方目录或压缩策略；第三方模型利用各客户端原生支持的窗口与压缩设置，不能声称有损摘要无损。aicli.third-party-continuity.v1 要求主动 compact 前，把目标和验收、约束/授权/owner、规则和关键文件、改动及脏改动归属、决定、测试/Live 缺口、阻塞与下一步写进项目已有状态；压缩后以摘要为线索，重读项目规则、状态文档及 git status/git diff。不建立第二事实源。一个会话/run 对应一个内聚里程碑，难题和最终判断不因节省 token 下放给能力未通过的模型。
- Codex machine run 的恢复只用官方 app-server 的 exact thread/resume，回读同一 thread/session、workspace、Profile 指纹、model/provider、requested/effective effort 和权限。AICLI 的最小恢复账本只证明身份、事件和回执，不保存任务正文、隐藏推理或工具载荷；无法证明原线程时不能把新线程或旧 partial 冒充恢复。实际模型身份须从 Profile 和受支持原生覆盖解析并回读，不把请求值直接标为 actual。工具、协议、权限、模型能力的证据分开记录。
- 本人要求第三方父任务能在 Luna 一轮完成后继续追问同一后台会话，运行中双向传补充、进度和问题，不让本人搬运消息，也不伪造原生子代理卡片。实现使用同一官方 Codex app-server：推理、工具、上下文、自动压缩和历史均归官方引擎；AICLI 只适配生命周期、父子绑定及消息投递，不直连 OpenAI HTTP、不复制聊天正文到自建账本。
- 普通父任务以 openai_child 创建或续同一 thread_id/model/reasoning_effort/task_name；子任务以 openai_parent 发进度或真实待答问题，父任务以 openai_child_control 查询、等待、停止。普通续问省略 reply_to；只有存在真实 pending question 时才回复其 reply_to/pending_reply_ids，不能用 final_message_id。一次回合结束不等于销毁持久会话；恢复核对身份并使用原官方线程，未确认投递或停止要明确报告。后台消息不是新的真人授权。旧父会话沿启动时的工具定义；新协议随新父会话生效。
- 受保护判断专用 openai_child 角色与普通后台协作分开：Sol High、Astra High 两档按当前活动保护合同选择；五个必填参数限定其判断范围，同步返回持久证据，不接受普通等待、续问或 fork 参数。角色、判断回执和线程标记不赋予 principal、授权或实施权。普通经济路由仍依真实用户许可约束厂商、型号、effort、任务范围和截止；许可未登记、撤销、到期、旧格式迁移、目录不可用要分别报告，不能误报成“超过父模型上限”。同一句旧授权出现在后续引用时，核对原始消息，不能把引用当新授权。

## 跨仓库接口、安装与恢复

- Toolkit 消费 aicli run --dry-run 的 aicli.machine-run-preflight.v1 结构化参数，不拼接旧 CLI flags；该预检在读取 stdin、建运行目录或调用模型前返回有效 Profile、模型、权限、预算和实际模块来源，并标明它尚未证明凭据或能力。Toolkit 的纯只读 inspect/jobs 与维护型 job 分开；诊断、控制文件身份、取消与终态应按 [Toolkit 集成合同](Toolkit-reliability.md) 执行。配置可解析、源码测试、安装副本、真实模型与用户 E2E 各是不同证据。
- Codex Desktop bridge 的内容寻址候选先构建，再由 PCConfig AuthorityHost 登记并安装精确七文件清单，之后才允许 AICLI Enable 和状态回读。文件数、路径、大小或 SHA-256 与已安装登记不符则失败关闭；AICLI 不自行加入信任清单。已安装、已启用和旧 Desktop 进程实际加载须分开判断，新工具定义需在实际新父会话回读。具体发布/回退版本去 PCConfig 与产品已有 desktop/acceptance 查，不把本文旧哈希当现状。
- 代理型 Claude 路线使用既有 raine/claude-code-proxy 与 router-for-me/CLIProxyAPI。只执行经产品批准的精确 SHA256 或可信发布者签名的 Windows artifact；代理仅监听 127.0.0.1。首选端口分别为 43197、43198，候选池 43192–43209；分配时检查 Windows 动态/排除范围、占用和真实 bind，成功验证进程身份及 listener 后才保存端口。停止、更新、卸载前重新核对 PID、启动时间、路径和 listener；不杀未知占用者，不修改系统端口范围、防火墙或 URL ACL。上游 OAuth 正文不由 AICLI 读取；本地文件删除与远程撤销分别报告。
- 用户 Profile/设置在 Windows Roaming AppData，秘密、代理、状态、缓存和日志在 Local AppData；模块安装于 CurrentUser PowerShell 模块目录，路径由 Known Folders/实际 PSModulePath 解析。API Key 采用 DPAPI CurrentUser，只在目标子进程环境传必要值；普通卸载保留用户 Profile、秘密、上游 CLI/登录和本地模型，显式 purge 才清本工具用户数据。受管文件若已被用户改写或身份未知，保留并报告。旧 Qwen3.7 退役迁移只隔离身份闭合的产物，保留新 exact 入口与 SecretRef。
- Doctor 默认做无模型生成的依赖、配置、身份和验证记录检查；无可靠零费用接口就写“未执行”。Live Test 需显式请求，使用真实目标 CLI 和隔离空目录；文本、工具、Agent 层各按实际事件及独立结果验证。工具测试仅暴露单用途 nonce 工具；无法隔离则跳过并报限制。测试记录绑定 Profile 指纹与实际入口，不存提示、回复、项目文件或秘密。两本 canonical Markdown 的 PDF 随文档交付时需核对源 SHA256、文本抽取和渲染页，不能只看转换进程退出码。

## Gemini 接入冻结

- 本人最初选择 Google AI Pro → 官方 Antigravity consumer → Gemini 推理 → Codex Harness。不可替代的边界是原生 Codex 独占文件、Shell、MCP、动态工具、权限、项目规则、上下文、压缩、thread 和历史；Antigravity 只做模型后端，不执行其自有工具，不使用 Gemini/Vertex API Key、逆向 OAuth 或自动 fallback。原设计详见 [D-036 V2](designs/D-036-v2-frozen.md)，未来型号资料在 data/gemini-models.json；这些是保留的设计与恢复资料，不表示当前可用。
- 后续真实日用连续验收未通过。本人于 2026-09-18 明确选择可逆冻结，并完成冻结审计；结论是 freeze_completed、integration_daily_use_not_delivered。仅 Gemini consumer → Codex 接入被冻结，AICLI、其他 Provider、官方 Antigravity CLI 不随之冻结。现行入口不得自动发现、启动、安装、启用、Live Test 或继续调试该接入；旧 enabled 记录及未来型号文件变化不能自动解冻。只有本人新的明确重开决定和新证据才可进入恢复工作，恢复步骤与保留物见 [Gemini 冻结与收尾](Gemini-integration-freeze.md) 和 [型号维护归档](Gemini-model-upgrades.md)。旧“可交 Desktop E2E”阶段判断已经被真实失败和最终冻结决定取代。
