## 2. 产品定义

一句话：让 Windows 用户用一个中文入口，按经过验证的 Profile 启动原生 Codex CLI、Claude Code 或当前官方 Rust Open Interpreter，不再反复手改全局环境变量、配置文件和代理进程。

本产品是启动与运维层，不是新的 AI Agent。聊天、历史、终端交互、权限提示、上下文管理和工具执行继续由原生 CLI 负责。

目标用户：

1. 已使用 Codex CLI、Claude Code 或 Open Interpreter，但需要切换官方订阅、国内 API 和本地模型的 Windows 用户。
2. 会使用 PowerShell，但不希望记忆 Provider、URL、套餐、模型和代理细节的用户。
3. 需要同一套可靠配置跨项目使用，同时不污染官方登录状态的用户。

核心原则：

- 原生优先：不重做 TUI、PTY、会话历史或协议网关。
- 明确选择：用户知道本次引擎、Provider、模型、凭据来源和数据去向。
- 进程隔离：不永久写全局 Provider 变量，不覆盖用户基础配置。
- 证据优先：能打开 CLI 不等于模型或工具可用。
- 安全失败：端口、身份、摘要、秘密和配置冲突不确定时拒绝危险动作。
- 可退出：`native` 和 `eject` 让用户能理解、迁移和脱离本工具。

2026-08-15 `0.3.11` 把 Codex machine run 从一次性 thread 改为可验证恢复的 root-owned run。首次启动使用 `thread/start ephemeral=false`，恢复必须使用 `thread/resume` 并回读原 thread/session、workspace、Profile 指纹、model/provider、requested/effective effort 和全访问权限。状态、事件与 receipt 在 `%LOCALAPPDATA%\AiCliProfileManager\state\recoverable-runs` 按 run/attempt 追加并使用单调 sequence/hash 链绑定；任务正文不持久化。瞬态中断最多自动 exact-resume 3 次，配额暂停不消耗重试次数；无法证明同一 thread 时必须新 workspace 全量重跑，旧 partial 永不合并。

2026-08-15 `0.3.12` 在该恢复控制面上增加显式 `--level agent` 验收，而不另建重试系统。验收只在新的临时目录运行确定性文件任务，要求真实工具活动，并由独立 verifier 校验结果；receipt 绑定 actual model/provider、CLI、五项全访问权限、exact thread/session、恢复次数、工具计数、清理与任务/verifier 哈希。模型自述、普通文本 Live、新 thread、身份漂移或 verifier 失败均不能通过。既有 `all` 保持 text+tool，不隐式触发 Agent 任务。

Open Interpreter 的旧 Python 0.4.x、LiteLLM 旧安装链和旧命令参数不属于支持面。

### 3.2 非目标

- macOS、Linux 和 Windows 11 以外的平台。
- GUI、全屏 TUI、PTY 外壳、内置聊天窗口或会话数据库。
- 修改或汉化上游 CLI 本体。
- 自研协议转换服务。
- 自动在不同 Provider 或双代理之间故障转移。
- 静默升级 Codex、Claude Code、Open Interpreter、Ollama 或账号相关组件。
- 交互式 `aicli start` 自动放宽上游审批或沙箱。面向程序的 Codex harness 是独立显式合同：所有当前及未来 Codex 模型固定完全访问。
- 未经验证就承诺智谱等未来 Provider。

## 4. 产品对象与数据模型

### 4.1 三层对象

1. **Provider 模板**：随版本发布的只读声明，记录引擎、Provider、套餐、地域、transport、端点、模型、认证类型、能力、来源和兼容性。
2. **用户 Profile**：保存模板 ID、用户自定义 ID/名称、地域、模型、项目偏好和秘密引用，不保存秘密值。
3. **启动计划**：每次 `start` 临时生成，包含可执行文件、工作目录、参数、子进程环境、移除变量、配置文件和代理依赖。

### 4.2 Manifest 基本字段

`schemaVersion`、`id`、`displayName`、`engine`、`provider`、`plan`、`region`、`transport`、`endpoint`、`models`、`auth`、`proxyRef`、`capabilities`、`compatibility`、`verification`、`sources`、`deprecation`。

Manifest 是无执行能力的数据，不允许嵌入 PowerShell。URL、Header、模型和 ID 在进入启动计划前验证；非 localhost 明文 HTTP 默认拒绝。

### 4.3 状态闭集

- `通过`：单个检查项成功。
- `可用`：当前版本要求的真实验证均有证据。
- `可用但有限制`：静态就绪、文本通过但工具未证明，或存在明确限制。
- `不可用`：关键依赖、协议、配置或真实测试失败。

验证记录必须绑定 Profile 指纹、引擎、Provider、transport、端点、模型、CLI 路径/版本、测试层和时间。配置或版本变化后旧证据不能无条件继承。

## 5. 锁定命令面

```text
aicli
aicli setup
aicli version

aicli profile list [--available] [--json]
aicli profile show <id> [--json]
aicli profile configure <template-id> [--id <profile-id>]
aicli profile set-default <id>
aicli profile remove <id> [--yes]

aicli start <id> [--project <path>] [-- <native-args...>]
aicli native <id>
aicli eject <id> [--output <path>]

aicli doctor [id] [--json]
aicli test <id> --live [--level text|tool|agent|all] [--yes] [--json]

aicli proxy <ccp|cliproxy> install
aicli proxy ccp login [codex|device]
aicli proxy cliproxy login [codex|claude|device]
aicli proxy <ccp|cliproxy> logout [--purge-local-auth] [--yes]
aicli proxy <ccp|cliproxy> configure [--port <port>|--auto-port]
aicli proxy <ccp|cliproxy> start|stop|status [--json]
aicli proxy <ccp|cliproxy> update-check|update|native

aicli update check [codex|claude|ollama|interpreter|ccp|cliproxy|self] [--json]
aicli update guide [codex|claude|ollama|interpreter|ccp|cliproxy|self]

aicli help [compact|model|effort|permissions|resume|compare|<command>]
aicli uninstall [--purge-user-data] [--yes]
```

规则：

- 无参数入口是短文本选择器，不是全屏界面。
- 未给 `--project` 时使用当前目录，目录必须存在。
- 只有 `--` 后的字符串逐项传给上游。
- 与启动计划冲突的 Provider、Base URL、认证和产品自管配置入口必须拒绝。
- 未知命令、参数和值缺失立即返回用法错误，不猜用户意图。
- 删除型动作默认确认；`--yes` 只授权该命令列出的本地删除。
- `test` 必须显式 `--live`；非交互需 `--yes`。

退出码：`0` 成功、`2` 用法错误、`3` 可用但有限制、`4` 不可用、`5` 内部错误、`6` 取消。

## 6. 文件、秘密与进程合同

### 6.1 默认布局

| 内容 | 位置 |
|------|------|
| 用户 Profile/设置 | `%APPDATA%\AiCliProfileManager` |
| 秘密、代理、状态、缓存、日志 | `%LOCALAPPDATA%\AiCliProfileManager` |
| CurrentUser PowerShell 模块 | 当前用户 `PSModulePath` 下的版本目录 |
| 命令垫片 | `%LOCALAPPDATA%\aicli\bin` |

所有路径通过 Windows Known Folders 或实际 `PSModulePath` 解析，不在公开模板中硬编码用户目录或盘符。

### 6.2 秘密

- API Key 使用 DPAPI CurrentUser；安全存储失败时不得回退明文。
- 秘密不得出现在 Git、命令参数、PowerShell 历史、日志、JSON、异常、`show`、`native`、`eject` 或测试快照。
- 代理 OAuth 由上游代理写入隔离目录，产品不读取 token 正文。
- 删除最后一个秘密引用的用户 Profile 时，可同时删除本工具保存的密文，但必须在动作前说明。

### 6.3 子进程

- 使用 `ProcessStartInfo.ArgumentList`，不拼接字符串执行，不对用户输入 `Invoke-Expression`。
- Provider 环境只进入目标子进程；父终端保持不变。
- machine child 先清空继承环境，再从 Windows、PowerShell、Node/TLS 所需的小型 allowlist 重建；父环境中的无关凭据、Provider 配置和调试变量不得默认进入子进程。受管计划最后通过 `EnvironmentDelta` 显式注入本次 Profile 必需的 Provider/运行时变量；该显式增量是受信任权限边界。
- `native` 必须展示脱敏后的实际计划；`eject` 只生成无秘密配方。

## 7. 引擎适配合同

### 7.1 Codex

- 公开第三方 transport 只接受 Responses。
- 交互式官方 Profile 使用真实 `CODEX_HOME` 与官方登录；machine run 只复制现有 `auth.json` 到独占 `CODEX_HOME`，不复制配置、规则、技能或其他会话，也不要求付费 API Key。可恢复 run 在终态前持久保留该 home 以支持真实 `thread/resume`；一次性 capture/Live 仍在结束时清理。
- 第三方 Profile 在真实 Codex home 下只写 `aicli-` 命名空间的独立 Profile 文件，并记录受管标记和内容 hash。
- 不覆盖基础 `config.toml` 或未知文件；用户修改后的受管文件不误删。
- 当前 Codex Profile 格式为 `$CODEX_HOME/<name>.config.toml`；旧 `[profiles.*]` 语法不作为当前合同。
- DeepSeek Flash 0731 与 Pro 0813 的官方模型身份分别进入隔离目录，并以内容寻址文件发布到 `aicli-model-catalogs` 受管命名空间；Profile 与 machine override 统一引用同一绝对 `model_catalog_json`。目录只含对应 exact alias，模型版本、Responses 与 max effort 纳入 Profile 指纹。
- Qwen3.8 Max 使用独立 `qwen3.8-max-codex.json`；Qwen3.7 06-08 使用独立 `qwen3.7-max-2026-06-08-codex.json`。两者固定 983616/95%、compact 262144 和用户 `max` → 原生 `xhigh`。其他 Qwen3.7 Max/Plus 的模型、兼容入口与生成分支仍为 tombstone；本地 `qwen-main-v1` 使用独立 262144 目录，`codex-ollama-review` 复用该 35B 目录作显式交叉入口，旧 `qwen-review-v1`/Qwen3.6 27B 身份为 tombstone；Qwen3.8-27B 使用固定 256K 运行标签及独立 `qwen3.8-27b-codex.json`。生成器除提示载荷外必须白名单声明能力，禁止照抄空 `base_instructions` 或静默继承其他 Provider 能力后宣称 Agent 行为不变。
- Claude/OpenCode 的模型窗口放在不可由用户 Profile 覆盖的 `modelMetadata`，纳入 Profile 指纹。非原生 Claude 只为命中元数据的已知最终模型注入 MAX/AUTO，未知模型清除五个上下文控制变量后使用上游保守默认；OpenCode 必须有 context/input/output/reserve/recent/tail 全集，否则启动失败关闭。
- 第三方 API Key 继续由 DPAPI CurrentUser 保存，只通过 Provider 的 `env_key` 对应环境变量进入目标子进程。禁止复制 DeepSeek 官方手工示例中的明文 `experimental_bearer_token`，也不写入 `preferred_auth_method`；AICLI 的隔离合同优先于方便配置的全局示例。
- Codex 思考强度通过当前构建的 `/reasoning`、`/model` 内的 reasoning effort 或配置字段 `model_reasoning_effort` 调整。
- Codex machine run 以当前实装并已验收的 npm `codex-cli 0.147.0` app-server JSON-RPC v2 为协议基线，由受管内部桥保持双向协议；后续更新版本只有通过同一运行时门禁才继续。所有当前及未来 Codex harness 模型在 `thread/start`/`thread/resume` 与 `turn/start` 都选择命名权限 `permissions=:danger-full-access`，并同时绑定 `approvalPolicy=never`；thread receipt 必须实际返回 `activePermissionProfile=:danger-full-access` 与 `sandbox.type=dangerFullAccess`。该不变量按 `engine=codex` 生效，不维护模型 allowlist；显式较低权限、权限身份缺失/漂移、审批或用户输入 RPC 均在模型调用前失败关闭。
- Codex harness 同样按 `engine=codex` 为当前和未来模型默认注册 `thread/start.dynamicTools` 的受管 `public_web_search`；只接受 exact `item/tool/call`、fixed `https://cn.bing.com/search` RSS 和有界参数/响应，拒绝重定向、Cookie、任意 endpoint/Header/凭据。系统代理只为固定 HTTPS 出口服务且不提供默认凭据。`dynamicToolCall` 投影为不含 query/result 的 `web_search` 生命周期；`--no-web-search` 是显式关闭，不得改变权限合同。
- Codex harness 直接运行 npm 包内与当前架构匹配的原生 `codex.exe`，不把短生命周期 Node 启动器作为可清理进程树的根；本地或云端模型都不再降级到外层 read-only/workspace-write 沙箱。其他引擎仍按各自 machine 合同使用外层 Windows 沙箱。任务正文不得写入 argv、环境变量、工作区或持久临时文件。
- Codex machine run 的有效模型必须在启动前从 Profile 默认值与受支持的原生 `--model` / `-m` 覆盖中解析一次，并一致绑定到 Provider `-c model=...`、machine plan、app-server `thread/start` 和公开运行回执。上层请求模型与有效模型不一致，或云端运行缺少有效模型回执时必须失败关闭；不得把请求值直接标成 `actual`。2026-07-28 曾因 bridge 从 Profile `primary` 重建模型而把 Flash/Plus 请求误发至 Max，相关旧 Live 身份证据已撤回。
- Qwen3.7 旧 Agent 记录不能直接恢复使用：只有新 Profile ID 与 exact 06-08 组合被允许，其他模型身份、旧 Profile、目录、导入和 native 参数继续失败关闭；它们不得被重路由到新入口或 Qwen3.8。
- 2026-07-29 的 Spark `workspace-write` 记录只保留为旧协议历史，已被 `0.3.5` 的通用 Codex `danger-full-access` harness 合同取代；权限通过、协议通过和模型能力通过仍必须分别记录。
- `0.3.12` 是当前源码与安装目标。验收记录必须绑定实际入口；在正式安装/候选切换前，不得用 source 结果声明 installed/runtime/live current。
- 观察层只接受 app-server 同一份完整运行时快照中的 `tokenUsage.total`、`tokenUsage.last.totalTokens`、`modelContextWindow` 与真实 `contextCompaction` item。运行累计 input/cache/output/reasoning/上游 total 必须来自 `total`；当前上下文必须来自 `last.totalTokens`。累计字段缺失时不得回退到 `last`，缓存为 `0` 时省略，缓存只作为输入子集展示且不得重复加入总计，推理输出保持独立。首次 run 建立 thread；后续 exact-resume 复用同一 thread，因此 `total` 是该 thread 的累计快照，每个恢复 attempt 的 usage 只能由单调累计快照差分得到；计数器回退必须失败关闭。不以配置上限或字符数估算。公开 `agentMessage` delta 按短语聚合成 `output.delta`；公开进度、粗粒度工具事件和最终结果可见，reasoning 正文不公开。`maxSteps` 采用 `distinct-non-output-thread-item-v2`，只约束不同的非输出行动 item；公开 progress/final message 不消耗行动步骤，但仍受墙钟、输出和事件门约束。0.145 的 `subAgentActivity` 是 completion-only 点事件；其他受支持 item 严格执行 started → completed，并绑定精确 thread/turn，成功轮次必须以 `status=completed` 结束。真实复杂任务证明 0.145 和 0.147 可能为多个公开进度消息省略 completion；兼容层按事件形态只把全部早于同轮次后续、已完成且有公开正文 final 的 `agentMessage` 标记为 superseded，后续保持相同结构的高版本自动继承。无后续 final、final 之后的新 orphan、任何非消息 orphan 或协议结构漂移不得兼容。事件文件不得保存 prompt、reasoning、命令、工具输出或压缩 history；低于基线、必要字段缺失或结构漂移、未知通知、scope/status/lifecycle 不合法、服务端请求或无法确认的 app-server 进程树清理必须失败关闭。

### 7.2 Claude Code

- 直连模板只接受 Anthropic Messages 兼容路径。
- `claude-custom` 要求 HTTPS 或 localhost HTTP、自定义 Key、主模型和可选小模型。
- ChatGPT 订阅只能通过明确标识的第三方 managed-proxy Profile，不伪装直连 Provider。
- Provider 环境只注入子进程，不自动改写用户/项目 `settings.json`。
- 启动前应计算会影响 Provider 的用户、项目、本地和受管设置层；无法安全隔离时阻止启动并指出文件和字段名。
- 权限与 effort 保留 Claude 原生语义；第三方 Provider 能力不得冒充官方模型等价能力。
- 非 Codex 的公开 DeepSeek 模板只允许 `deepseek-v4-flash`；Codex 的 Flash 0731 与 Pro 0813 使用两个隔离 exact Profile。2026-07-14 的旧 Pro Live 记录因 Profile 指纹变化只保留为历史事实，不证明当前任一 Codex 路径。

### 7.3 Open Interpreter Rust

- 只接受当前官方 Rust CLI `0.0.21+`；检测并拒绝旧 Python 0.4.x。
- 千问与 Ollama 使用 Responses wire，DeepSeek 使用 Chat wire。
- 公开 DeepSeek 模板只允许 `deepseek-v4-flash`；旧 Pro Live 记录不得跨当前模板指纹复用。
- 通过临时 `-c` TOML 覆盖设置 `model_provider`、`model`、`base_url`、`wire_api` 和 `env_key`，不写旧 YAML Profile。
- 云端 Key 只进入 `AICLI_OI_PROVIDER_KEY` 子进程环境，并通过 `shell_environment_policy.exclude` 从 Shell 工具排除。
- 不启用旧版自动执行、命令行明文密钥或任何审批/沙箱绕过参数。
- Live 文本测试使用真实目标 CLI 与临时空目录。Codex 统一走 app-server `danger-full-access`，以观测到零次工具调用作为通过条件并回读权限身份；首个工具事件触发终止，但不冒充执行前工具禁用。其他引擎继续使用各自可证明的工具禁用、配置隔离与较低权限路径。

## 8. ChatGPT 双代理与端口合同

固定上游：

- `ccp`：`raine/claude-code-proxy`，首选端口 `43197`。
- `cliproxy`：`router-for-me/CLIProxyAPI`，首选端口 `43198`。

### 8.1 供应链

- 任一 Windows artifact 必须匹配产品随版本发布的精确 SHA256，或固定可信发布者签名。
- HTTPS、GitHub 来源、下载后临时算摘要或“上游没有 checksum”不能替代批准证据。
- 解压前枚举条目并拒绝绝对路径、`..`、链接逃逸和清单外可执行文件。
- 首次安装在临时目录完成摘要、安全解压和结构验证后才设置 `current`；启动时完成进程身份、健康响应与 loopback 监听验证后才保存运行状态。`0.1.0` 不执行已安装代理的受管版本切换；后续版本若启用更新，必须先完成运行健康验证并支持失败回滚。

### 8.2 端口

- 只允许 IPv4 loopback `127.0.0.1`；`0.0.0.0`、`::`、局域网和公网监听均失败并停止本次受管进程。
- 候选池为 `43192-43209`，两个代理采用不同轮转起点。
- 分配时持有同用户互斥锁，排除 TCP 动态范围、Windows excluded ranges、活动 listener 和真实 bind 失败。
- 不修改动态端口范围、excluded range、防火墙或 URL ACL，不杀未知占用进程。
- 成功启动并验证新进程持有 listener 后才持久化端口。

### 8.3 身份和生命周期

运行状态记录代理 ID、PID、启动时间、可执行路径、版本目录、配置路径、host、port 和 nonce。停止、更新或卸载前重新核验 PID、启动时间、路径和 listener；身份不匹配不终止。

登录只调用上游交互，不读取 OAuth 正文。`logout` 必须分别报告本地清理和远程撤销；强制删除本地认证目录不等于远程撤销。

## 9. Doctor 与 Live Test 合同

### 9.1 Doctor

按稳定 check ID 检查：平台与 PowerShell、CLI/代理/Ollama 版本、安装来源、登录状态、Manifest/Profile/schema/秘密引用、父环境与有效配置层冲突、套餐/地域/端点/模型、代理身份和 listener、Ollama 服务/模型、验证记录有效性。

Doctor 默认不发模型生成请求。没有安全、零费用认证接口时明确写“未执行”，不得用自制 HTTP ping 冒充目标 CLI 已通过。

### 9.2 Live Test

1. 必须显式 `--live`，先展示 Provider、数据去向和额度风险。
2. 创建随机临时空目录，不读取用户项目。
3. 使用真实目标 CLI 的非交互入口。Codex 保持通用 `danger-full-access` 合同，并且只有最终观测到零次工具调用才通过；首个工具事件触发终止，但不是执行前工具禁用。其他引擎隔离私人规则、设置、MCP、Hooks、Skills 和普通工具。
4. 文本层要求进程退出码 0 且最终模型正文严格等于 `PONG`。
5. 工具层只暴露不接受任意路径/命令的 nonce 工具；无法隔离时跳过并报告限制。
6. 保存结构化版本和 Profile 指纹，不保存提示、回复、项目文件或秘密。
7. `finally` 清理临时配置、工具进程和目录；异常也要覆盖旧验证记录。

## 10. 安装、更新、卸载和恢复

### 10.1 安装

- CurrentUser PowerShell 模块，不需要管理员权限，不全局放宽 ExecutionPolicy。
- 从 Manifest 读取版本，复制到临时候选目录并导入验证。
- `-Force` 才允许替换已有同版本；替换失败恢复备份。
- 创建用户 PATH 垫片并尝试加入 PowerShell 自动导入块。
- 用户数据独立于模块版本，重装或上游 CLI 更新后仍可重新生成启动计划。

### 10.2 更新

- 先识别实际安装来源，再给同渠道命令。
- 不混用原生安装器、npm、WinGet 等渠道。
- 上游 CLI 只检查和指导，不静默升级。
- Open Interpreter Rust 可使用当前官方 `interpreter update`。
- 受管代理只有批准 artifact 才显式更新并支持回滚。
- 本工具 self update 在有真实 GitHub Release 来源后才启用。

### 10.3 卸载

- 普通卸载停止己方代理、删除模块，保留 Profile、DPAPI 秘密、代理数据和导出物。
- `--purge-user-data` 才删除本工具 AppData/Local 数据。

- 删除代理本地 OAuth 前先执行或引导 logout，并分别展示本地删除与远程撤销状态。

### D-010 至 D-018：安全与运维

- D-010：不自动故障转移或静默升级。
- D-011：交互式 `aicli start` 默认不绕过原生权限。该历史决定不适用于 D-033 明确规定的 Codex harness。
- D-012：上游更新只检查和指导。
- D-013：代理端口动态验证、成功后持久化。
- D-014：中文手册先讲用途、命令和效果。
- D-015：项目代码使用 MIT License；第三方许可证独立。
- D-016：秘密使用 DPAPI CurrentUser。
- D-017：CurrentUser PowerShell 模块安装，不要求管理员。
- D-018：首版命令面锁定，品牌和版本应集中定义。

### D-019 至 D-027：验证与实施修正

- D-019：Ollama 不设跨硬件万能推荐模型；公共模板只使用标准端口和公开模型。
- D-020：未知代理二进制绝不下载执行。

- D-027：统一 JSON 外壳、开发入口、代理型 eject 锁文件、离线 Smoke/CI 和兼容性单页作为实施增强。

### D-028：Open Interpreter 世代切换

首版只支持当前官方 Rust Open Interpreter `0.0.21+`，拒绝旧 Python 0.4.x。Provider 采用 Rust CLI 的 TOML 配置与环境密钥引用，不能把旧参数兼容层继续作为公开能力。

### D-029：DeepSeek Codex Flash/Pro exact 接入

`0.3.4` 将 Codex 的 `deepseek-v4-flash` / `DeepSeek-V4-Flash-0731` 与 `deepseek-v4-pro` / `DeepSeek-V4-Pro-0813` 分成两个 Responses exact Profile，均固定 1M 与用户默认 `max`。Claude Code 走 Anthropic、Rust OI 走 Chat，并继续保持 Flash-only。Qwen Code 0.21 与 OpenCode 1.18.8 即使有上游原生支持，也不能绕过 AICLI 当前禁网 machine 沙箱：在真实 Key 可能进入 Shell 且缺少受控远程 egress relay 时，不创建假 Profile。

### D-030：第三方上下文连续性以原生 ChatGPT + Codex 为基准

原生 `codex-official` 不附加目录或压缩策略。第三方 Codex 无 OpenAI remote compact 时使用受管模型目录修正真实窗口，云千问与本地 Qwen 分离；Claude Code 只为已知模型设置官方支持的窗口变量，不设置提前压缩百分比，也不禁用溢出保护，未知模型会清除继承控制项；OpenCode 的一次性配置对 `qwen-main-v1` 显式声明 262144/8192，对固定 Qwen3.8-27B 256K 运行标签声明 262144/32768，并共用 20000 reserve、4 轮/16384 token 保留与 `prune=false`。这些设置只能延后并减少不必要的有损摘要，不能把摘要宣称为无损。

AI 使用合同：一个会话/run 对应一个内聚里程碑；AICLI 的 `aicli.third-party-continuity.v1` 契约要求主动 compact 前先把目标与验收、约束/授权/owner、规则与关键文件、改动及脏改动归属、决定、测试/Live 缺口、阻塞与下一步持久化到项目已有状态，压缩后把摘要当线索，重读项目规则、状态文档与工作树（`git status`/`git diff`），不建立第二事实源。难题与最终判断不得为节省 token 下放给能力未通过的模型。远程 Qwen/DeepSeek OpenCode 仍受 key-isolated egress relay 门禁，与压缩修复相互独立。

### D-031：PDF 构建必须有界并可视觉复核

两本 canonical Markdown 的 PDF 构建优先使用仓库随附 helper 调用本机已有 Playwright 与 Edge，隔离于日常浏览器进程；缺少该运行时时才进入有界超时的 Edge CLI 后备。生成物必须记录源 Markdown SHA256，完成文本抽取、全页渲染和代表性密集页检查后才能随文档提交，不能把“进程退出码为零”单独视作版面通过。

### D-032：Qwen3.7 Max/Plus 永久退役

Qwen3.7 Max/Plus 全家族不再是候选或兼容层：移除 Codex、Claude Code、Open Interpreter Manifest、目录、生成器分支和 OpenClaw 导入入口；旧用户 Profile、最终启动计划以及 native model/fallback 参数都必须命中统一 tombstone 并失败关闭。退役身份不能自动映射到 Qwen3.8，也不能通过旧安装 payload 或遗留受管 Codex 文件继续启动。

升级安装必须先作全量预检，再把身份闭合的退役入口移入可恢复 quarantine；任何未知或用户改写项阻断本次安装且不被删除。用户 SecretRef 保留，后续只能在身份相同的凭据域内显式复用，不进行明文迁移。

### D-033：所有 Codex harness 当前及未来模型一律完全访问

`aicli run` 的 Codex 路由按引擎而不是模型列表固定原生 `danger-full-access` 与 `approvalPolicy=never`。每个新模型、Provider 或本地 Profile 自动继承同一权限合同；请求较低权限不是兼容模式，而是调用前错误。桥接器必须从 app-server 回读 `dangerFullAccess`，同时回读 exact model/modelProvider 并拒绝 reroute。交互式 `aicli start` 仍由用户和原生 CLI 管理权限，不与 harness 合同混淆。

Codex 文本 Live 也必须走该通用 harness，并保存 exact runtime executable/version 与 `approval_policy`、`requested_policy`、`sandbox_boundary`、`sandbox_type`、`permission_profile` 五项运行时证据。本次 Live 额外要求观测到零次工具调用；首个工具事件触发终止和失败，但该机制不是执行前禁用、沙箱或降权。

### D-034：窄恢复 Qwen3.7 Max 06-08 exact Codex Profile

用户 2026-08-14 的新明确指令窄范围取代 D-032 的“全家族永久退役”：只新增 `codex-qwen3-7-max-paygo` → `qwen3.7-max-2026-06-08`。该入口固定北京 Workspace paygo Responses、单候选、无 fallback、983616/95%、compact 262144，并把用户 `max` 映射原生 `xhigh`。同一 Workspace endpoint 才可显式复用 Qwen3.8 的不透明 SecretRef。

D-032 对通用 `qwen3.7-max`、05-20、preview、Plus、旧 Profile ID、Claude/OI/OpenClaw route、native model/fallback 和旧安装入口继续有效。06-08 仍在全局 tombstone matcher 中，以阻止自由模型覆盖；只有同时命中新 exact template/profile identity 的上下文门才允许。迁移同样必须按身份保留新 exact artifacts，而不是把“出现 06-08 字符串”直接当作旧入口。

### D-035：exact Codex Profile 使用快速启用与正式发布双车道

维护者从 clean commit 本机启用一个 exact Codex Profile 时，使用 `Install-ExactCodexProfileFast.ps1`。快速车道必须闭合 Manifest/目录单模型身份、Responses、`flexible=false`、用户 `max`、无 reserved/fallback、退役上下文门、one-command、SecretRef 与安全回归，再执行发行 smoke、原子安装和固定 shim 的 `list/show` 回读；它不得构建 PDF/ZIP、执行付费 Live 或把 `liveAcceptance=not-run` 冒充当前 Live。

正式公开发布仍需全量 Pester、canonical 文档/PDF、发行 ZIP/hash、公开暴露检查、Git 收口以及按授权执行的独立 Live。两条车道共享同一 source of truth；快速车道缩短本机可用等待时间，不降低 exact/no-fallback/secret/launch-plan 门禁。`--reuse-secret-from` 命中同一 Qwen Workspace 凭据域时同时盲复用规范化 endpoint，避免重复输入或回显 Workspace 标识。

## 16. 动态事实纠正记录

- Codex 当前 Profile 是独立 `<name>.config.toml` 文件，不使用旧 `[profiles.*]` 嵌套方案。
- Codex 第三方 Provider 只接受 Responses wire；Chat Completions 不能只改 Base URL 强行接入。
- DeepSeek Codex/Responses 当前官方 alias 包括 `deepseek-v4-flash` 与 `deepseek-v4-pro`；AICLI 还分别固定 Flash 0731 / Pro 0813 版本元数据。官方示例允许的全局明文 Key 写法不属于 AICLI 安全合同。
- 千问按量、Token Plan 和 Coding Plan 的 Key、端点与能力必须分开。
- 双代理是第三方本地程序，不是 OpenAI/Anthropic 官方能力。
- Codex reasoning effort 通过当前构建的 `/reasoning`、`/model` 内选择或配置字段调整。
- Open Interpreter 当前官方实现为 Rust；旧 Python 文档、参数和本机验证记录全部失效，必须重新验收。
- 讨论归档或截断输入不能直接成为实现真相。

## 18. 公开发布完成定义

发布前必须同时满足：

1. 干净 Windows 11 标准用户可安装、重装、升级、卸载和恢复。
2. 所有公开命令、未知参数、中文/空格路径和退出码自动测试通过。
3. 两本 canonical 手册与实现一致；旧页面仅作迁移入口。
4. 三套思考命令不混用，OI 文档无旧 Python 安装步骤或旧接口。
5. Release ZIP 不含机器私有路径、研究输入、原始日志、秘密或维护者规则。
6. ZIP、SHA256、SBOM/第三方版本清单和许可证齐全。
7. 当前 Provider 矩阵有真实目标 CLI 的版本、模型、端点、指纹和结果；未测路径明确标待验收。
8. 双代理仍为可选第三方通道；未完成 OAuth/Live 时不标可用。
9. GitHub Security 私密报告入口、隐私、贡献、第三方声明和 Changelog 可用。
10. 公开远端、push、PR 和 Release 只在获得明确授权后执行。
